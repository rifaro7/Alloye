ALY-DOC-01

Architecture — headless by design

Alloyé runs as two separate systems that never let the customer see the second one.

The storefront customers browse is a set of static, hand-coded HTML pages. It calls a small layer of PHP scripts, which in turn talk to a WordPress + WooCommerce installation on a separate subdomain. WooCommerce is used purely as a database and an admin dashboard — its own theme and checkout are never rendered to a customer. This split was the starting requirement: the store owner needed to add products, change prices, and manage stock from a familiar dashboard, without ever touching code.

The only two-way trust relationship is between the PHP scripts and WooCommerce's REST API, authenticated with a consumer key and secret stored in a single file that is never shipped to the browser or committed to source control.

ALY-DOC-02

Frontend — static pages, no build step

Seventeen hand-written HTML pages, one shared stylesheet, four JavaScript modules. No React, no bundler — deliberately, since the whole point is a page that loads instantly on a mid-range Bangladeshi phone connection.

PageJob
index.htmlHomepage — hero, category entry points
shop.htmlFull catalogue with category / search / sort filters
product.htmlProduct detail — gallery zoom, related pieces, structured data
cart.html / checkout.htmlBag review and the order form itself
account.html / order-tracking.htmlSign in, order history, delivery status
wishlist.htmlSaved items, stored client-side
about / contact / faq / shipping / returns / privacy / termsStore policy and trust pages
order-confirmation.html / 404.htmlPost-purchase receipt and error page

Shared modules

  • products.js — fetches the live catalogue from get-products.php and renders product cards and the detail view.
  • cart.js — the cart and wishlist live entirely in the browser's localStorage; no login is required to shop.
  • main.js — navigation, the search overlay, and small interface behaviour shared across pages.
  • pixel.js — fires Meta Pixel events (see §07).

Typography is Cormorant Garamond paired with Jost, loaded once via Google Fonts. Every stylesheet and script is loaded with a ?v=2 version tag — the host's 7-day browser cache header was silently hiding CSS fixes from returning visitors until this was added.

ALY-DOC-03

Backend connector scripts

A small set of framework-free PHP files, each doing one job, each talking to WooCommerce over cURL with Basic Auth.

ScriptResponsibility
get-products.phpReads the live catalogue and computes badges (Best Seller from real sales count, New from listing age)
create-order.phpValidates stock, applies coupons, places the order, emails the receipt
check-coupon.phpValidates a coupon code against WooCommerce before it's shown as a discount
register.php / my-orders.phpCustomer sign-up and order history, authenticated by JWT
send-message.php / subscribe.phpContact form and newsletter sign-up
smtp-mailer.phpA dependency-free SMTP client over Gmail — the host's built-in mail() was unauthenticated and unreliable

Every script requires config.php, a single file holding the WooCommerce API key/secret, the store's notification email, and the SMTP credentials. It is blocked from direct web access by .htaccess and excluded from Git — see §08.

ALY-DOC-04

How an order is actually placed

The frontend's job is to look right. The backend's job is to not trust it — every check that matters is repeated server-side.

  1. Cart reviewItems, quantities and any applied coupon are read from localStorage on cart.html.
  2. Checkout formCustomer enters contact details, address, delivery area and payment method (Cash on Delivery today).
  3. Live stock re-checkcreate-order.php re-fetches every item from WooCommerce and rejects the order with a clear message if anything has gone out of stock since it was added to the cart.
  4. Customer lookupIf the checkout email matches an existing WooCommerce customer, the order is linked to that account automatically.
  5. Coupon applied by WooCommerce, not the browserThe coupon code is passed to WooCommerce's own coupon_lines, so WooCommerce — not the frontend's arithmetic — decides the final discount.
  6. Order createdA real WooCommerce order is created with status "processing," billing and shipping details, and the chosen delivery method.
  7. Confirmation email sentThe customer receives an order number, item list, total and a tracking link, sent through the custom SMTP mailer.
  8. Cart clearedThe frontend clears the local cart and coupon, and redirects to order-confirmation.html.
The out-of-stock check exists because the "Add to Cart" button being disabled isn't enough — a product can sell out after it was added to someone else's cart. This was tested against a real out-of-stock product before launch.
ALY-DOC-05

Coupons & discounts

Coupons are ordinary WooCommerce coupons — the store owner creates one from the wp-admin dashboard (a percentage or fixed amount, with optional expiry, usage limit, and minimum spend) and it works on the live site immediately, with no code changes. On the cart page, check-coupon.php checks the code's validity and shows the discount; at checkout, the code travels with the order so WooCommerce applies the same discount authoritatively. This closed an earlier gap where a coupon looked applied on the cart page but was silently dropped by the time the real order was placed.

ALY-DOC-06

Accounts & login

Shopping never requires an account. Customers who do register authenticate against WordPress itself, via the JWT Authentication plugin — the site never stores or checks a password of its own. A signed-in customer sees their real order history and status on account.html, pulled live from WooCommerce. Password recovery links out to WordPress's own reset flow rather than a custom one, since that's the safer and already-hardened path.

ALY-DOC-07

SEO & marketing tracking

  • Meta Pixel — fires PageView, ViewContent, InitiateCheckout and Purchase events, ready for Facebook/Instagram ad retargeting.
  • Google Analytics 4 — a dedicated property under the store's own account (not a personal one), tracking real visitor behaviour separately from ad data.
  • Structured data — each product page carries schema.org Product markup (price, currency, stock status), so Google search results can show price and availability directly.
  • Open Graph tags, meta descriptions, sitemap.xml and robots.txt are set on every page.
ALY-DOC-08

Security decisions

  • The WooCommerce API key/secret and SMTP password live only in config.php — blocked from direct browser access by .htaccess, and excluded from Git entirely (it has never been committed, even though the repository itself is public).
  • Stock and coupon validity are decided on the server on every order, never trusted from the browser.
  • Customer authentication is fully delegated to WordPress's own JWT plugin — no custom password handling exists anywhere in the connector scripts.
  • The GitHub repository is public for portfolio purposes but carries an All Rights Reserved license — visible code, no license to reuse it.
ALY-DOC-09

Hosting & deployment

The domain and hosting both sit with Namecheap: alloye.shop on a Stellar Plus shared plan, with cms.alloye.shop as the WordPress subdomain on the same account. SSL is active on both. There is no CI/CD — a deploy is a manual step: changed files are zipped locally, uploaded through cPanel's File Manager, and extracted over the live public_html directory, overwriting what's there.

Hosting is due for renewal on 22 September 2026; auto-renew is currently switched off, so this is a manual date to track.

ALY-DOC-10

Pre-launch fix log

Issues found during a full pre-launch audit, and how each was actually resolved — kept here so the reasoning isn't lost.

  • FOUND — inaccurate product claims"Waterproof stainless steel," "hand-finished," and "designed in-house" were removed sitewide — no longer accurate once newer pieces were sourced wholesale.
  • FOUND — out-of-stock items were orderableAdded the server-side stock re-check in create-order.php described in §04; verified against a real sold-out product.
  • FOUND — coupon discount lost at checkoutRebuilt the flow so the coupon code is sent with the order and applied by WooCommerce itself, not just calculated on the cart page.
  • FOUND — missing price strikethroughFixed CSS so the original price shows struck through on the product detail page, matching the shop grid.
  • FOUND — CSS/JS fixes not appearing for returning visitorsTraced to the host's 7-day cache header; solved permanently with versioned ?v=2 query strings.
  • FOUND — slow-loading product photosDownloaded, compressed to WebP, and re-uploaded every bloated product image; some dropped from over 1.5 MB to under 100 KB.
  • FOUND — fabricated trust signalsRemoved invented customer reviews and a "Best Seller" badge with no real sales behind it; badges are now computed from actual WooCommerce order data.
  • FOUND — no self-service password recoveryAdded a "Forgot password?" link to WordPress's own reset flow.
  • FOUND — no order confirmation emailcreate-order.php now sends the customer a receipt through the custom SMTP mailer once the order is placed.
ALY-DOC-11

Known limitations

  • bKash is not yet live — shown as "Coming Soon" in checkout; Cash on Delivery is the only working payment method today.
  • Deployment is manual — there is no automatic pipeline from GitHub to the live server; every update is a hand-run upload.
  • Shared hosting ceiling — Stellar Plus is sufficient for current traffic, but a real spike (a viral post, a large ad campaign) would be the first thing to outgrow it.
  • No WhatsApp contact channel yet — identified as a likely high-value addition for Bangladeshi customers, not yet built.
